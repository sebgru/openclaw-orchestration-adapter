# Orchestration 2.0 (prototype coordinator procedure)

The main session is the coordinator and stays accountable for the plan, routing, task lifecycle, verification, owner summaries, and dashboard. Workers execute one bounded task and return evidence. This skill is self-contained; it adds no tools, config, or ceilings.

## Rules (acceptance cues in brackets)

1. **Standard spawning only.** Create every ordinary worker with OpenClaw `sessions_spawn`. Do not use `orchestration_dispatch`, `orchestration_run_plan`, or adapter `api.runtime.subagent.run` for ordinary work. Workers run under normal OpenClaw policy, including the standard host sub-agent tool restrictions; this skill never adds or implies a hidden tool/model ceiling, and the worker's tool set is not assumed to equal the parent's. Before dispatch every task brief states `required_tools` and `inherited_tool_evidence`; the parent's tool catalog alone does not prove the child has a tool. If a required tool cannot be evidenced, do not dispatch; mark the task `blocked` and record the gap. [CUE:STANDARD_SPAWN] [CUE:TOOL_EVIDENCE]
2. **Bounded adapter dispatch is an explicit exception.** Use it only when the owner asks for a least-privilege, grant-limited worker, or a task needs enforced per-run tool/budget limits. Record the exception and reason in the task record. It is never the default. [CUE:ADAPTER_EXCEPTION]
3. **Canonical task state.** Keep one plan file (e.g. `projects/<name>/README.md`) with per-task: id, goal, deps, status (`pending|ready|running|verifying|done|blocked|gated`), requested route, actual route, run id, timeout, evidence, next action. Only the coordinator edits it. [CUE:TASK_STATE]
4. **Self-contained brief before dispatch.** Include: goal and concrete deliverable; observable pass/fail criteria; evidence to return and where; dependencies; exact write scope; selected model; timeout; optional budget (state which parts are advisory vs host-enforced; only the run timeout is host-enforced); stop/escalation conditions; "do not delegate; report blockers instead of inventing criteria." The brief's scope, tool, and no-recursion restrictions are prompt-only (intent, not host-enforced); only the run timeout and normal host policy are host-enforced. Resolve any ambiguous criterion before dispatch. Scope text is intent, not a security boundary. [CUE:BRIEF] [CUE:PROMPT_ONLY]
5. **Choose and record the route.** Pick a registered, callable, policy-permitted model per the deployment routing policy, preferring eligible Claude models when they fit. Record requested model and reason. After spawn, read the receipt and record the actual model/provider. If the exact requested route is unavailable or the actual differs from the approved choice, halt that task, mark `blocked`, report; never substitute silently. [CUE:ROUTE_RECORD]
   - **Worker model confirmation first.** The brief's first instruction, before any substantive analysis, is: confirm your runtime model identity matches the exact approved model; if it does not, stop and report. [CUE:WORKER_MODEL_CONFIRM]
   - **Coordinator receipt gate.** Immediately after spawn, require receipt-confirmed `resolvedModel`, `resolvedProvider`, and `runId`; any missing, unconfirmable, or mismatched value blocks the attempt: cancel via `subagents` when possible, reject all output, record the exact gap, and inspect possible partial side effects before any retry. Preserve the requested timeout from the brief. If the receipt echoes an applied timeout, record and compare it; a mismatch blocks the attempt. If it does not echo an applied timeout, record `applied_timeout=unconfirmed` and retain the requested timeout as the intended host limit; this gap alone does not invalidate an otherwise valid worker or model/provider receipt. Never claim the requested timeout was receipt-confirmed as applied. [CUE:RECEIPT_FAIL_CLOSED] [CUE:TIMEOUT_UNCONFIRMED]
   - **Disclosure.** `sessions_spawn` starts the child immediately. This worker self-check plus receipt check is a compensating prompt/receipt gate, not a host-held pre-analysis gate; the worker may already have run when a mismatch is detected. [CUE:GATE_DISCLOSURE]
6. **Observe, steer, cancel.** Confirm the dispatch with the receipt; use `sessions_yield` to wait for completion events (no busy polling); use `subagents` list/`sessions_history` only for status/debugging; clarify with a steer message when needed; cancel via `subagents` cancel on timeout, wrong direction, or owner stop. Detect failure, timeout, and missing evidence. Because no-recursion is prompt-only, explicitly detect unexpected descendants: check `subagents` list for children of the worker and require the worker's report to include `subagent_used`. Cancel any unapproved descendant, and do not accept its output as evidence without independent verification. [CUE:DESCENDANT_DETECT] Retries are bounded, justified, and never repeat side effects blindly (check the worktree/outputs first). [CUE:LIFECYCLE]
   - **Completion-driven chains.** For an authorized dependency chain that should progress without an owner prompt, spawn hidden native one-shot workers with `completionTarget: "parent"`, record the run ID, then call `sessions_yield`. On the resumed parent turn, match the completion to the recorded task, verify it, update canonical state/dashboard, and dispatch the next ready task. This option returns a private parent turn; it does not itself perform verification or scheduling, which remain the coordinator model's responsibility. Follow [`docs/completion-driven-continuation.md`](../../docs/completion-driven-continuation.md) for limits and recovery. [CUE:PRIVATE_PARENT_CONTINUATION]
7. **Verify independently.** A completion claim is not evidence. Re-run the checks or read the artifacts yourself against each criterion. A task is `done` only after that. Review tasks go to a fresh worker with a filtered brief (no author reasoning). Rejected review: record findings, create a fix task, re-review. [CUE:VERIFY]
8. **Progress automatically.** After verification, update the canonical state, compute the next `ready` task (all deps `done`, not gated), and dispatch it without asking the owner. Stop only for a gate, blocker, or completion. [CUE:AUTO_PROGRESS]
9. **Dashboard before completion.** After recording a verified result, synchronize the hosted dashboard from canonical state and confirm it shows the new status; only then report the task complete. If the dashboard update fails, the task is not complete. [CUE:DASHBOARD_SYNC]
10. **Owner summaries with evidence.** At milestones, blockers, gates, and completion: what completed (with evidence refs), the receipt-confirmed actual worker model/route for each task, current remaining state (running/remaining/blocked), next action, and any owner decision needed. Concise. [CUE:OWNER_SUMMARY] [CUE:SUMMARY_ROUTE]
11. **Human gates.** Stop and present the reviewable artifact for: PR review/merge, push where approval is required, OpenClaw config or model-routing changes, Gateway restart/activation. Continue independent authorized work meanwhile. Approval for one gate does not authorize another. [CUE:HUMAN_GATE]
    - **Owner decision gate.** For a material unresolved owner choice or a protected action, stop and request Sebastian's decision. State the exact decision or action needed and give concrete reviewable options or an artifact. Meanwhile continue independent authorized work that does not depend on the answer. [CUE:OWNER_DECISION_GATE]
12. **Worker tree.** Only the coordinator spawns; workers may propose splits but do not spawn by default. [CUE:CENTRAL_DISPATCH]
13. **Denials are reported accurately.** Surface actual tool denials as such; do not describe them as task failure or a worker error. [CUE:DENIAL_VISIBLE]

## Durable ledger (optional)

When a task ledger is configured, the local `bin/coordinator-ledger.js` bridge can write it without plugin configuration when shell access and this checkout are available. It cannot spawn, yield, verify, publish, or authenticate owner decisions. Follow the write/continuation order in [`docs/completion-driven-continuation.md`](../../docs/completion-driven-continuation.md#coordinator-writecontinuation-procedure). Ledger acceptance output is coordinator-asserted; never report it as live acceptance without owner review of the run log, and never record an owner decision without an authenticated owner message.

## Three-dependent-task trial shape

T1 implement -> T2 verify/test (deps T1) -> T3 independent review (deps T2), then gate G1 human PR review. Pass when the log shows: three standard `sessions_spawn` receipts with recorded actual models, zero owner nudges between T1-T3, each task `done` only after coordinator verification and a dashboard sync, and the run halted at G1 with no adapter dispatch.

## Done when

Every task is `done`, `blocked`, or `gated` in canonical state; the dashboard matches; and the owner has the final summary with evidence and the next gate.
